## 排障记录：提醒通知不出现（用户反馈"内嵌窗口可以顺利打开，但是没有看到提醒通知"）

### 第一层根因：测试污染真实设置
- `test_reminder.py` 运行时会创建临时库并写入 `settings.json`，但只重定向了 DB 路径，**漏了 SETTINGS_PATH**
- 测试把真实 `data/settings.json` 的 `remind_enabled` 写成了 `false` → 提醒被全局静默关闭
- 修复：4 个测试文件全部补 `db.SETTINGS_PATH = os.path.join(_tmp, "settings.json")` 隔离；恢复真实设置为 `{"remind_enabled": true, "remind_days": 1}`

### 第二层根因（真正 bug）：ALTER TABLE 加的列是 TEXT 类型
- 真实库是旧表结构，靠 `ALTER TABLE ADD COLUMN` 加 `remind_days`，**SQLite 加出来的列是 TEXT 类型**
- 读出的是字符串 `'1'`，与整数比较抛 `TypeError: '<' not supported between instances of 'str' and 'int'`
- 结果：提醒线程**从启动起每个 tick 都在崩溃**，从未成功工作过
- 测试库是新表（INTEGER 列），读出自动转 int，所以测试 9/9 通过——**测试覆盖盲区**
- 修复：读取时防御性 `int()` 转换

### 修复验证
- 主程序日志确认：`[提醒] 2026-08-26 检查到 2 条待提醒卡片`
- 用户确认看到 Windows 托盘通知 → **提醒链路真机验证通过**

## 经验教训
1. **测试隔离必须三件套齐全**：DB_PATH + MEDIA_DIR + SETTINGS_PATH，漏一个就会污染真实数据
2. **ALTER TABLE 兼容性**：旧库升级的字段必须假设类型可能是 TEXT，读出来一律强转
3. 测试库结构与真实库不一致会掩盖线上 bug——迁移类代码要专门验证真实库形态
