## 二、全局热键排障（本项目最有价值的"问题分析"素材）

### 现象
用户微信里复制文字后按 Ctrl+Shift+V 无反应。热键注册返回成功，但按键从不触发。

### 六轮诊断
1. 排除注册失败/热键冲突（RegisterHotKey 返回 True）
2. 发现键盘钩子装不上（ctypes 64 位指针截断：HHOOK 用默认 c_int 会截断）
3. 窗口级注册也失败（err=1409，实际是被线程级注册抢占）
4. 用户手动按键确认，WM_HOTKEY 从不进入线程消息队列
5. 钩子修好后仍捕获不到任何按键 → 怀疑消息派发层面
6. **决定性实验**：QInputDialog 输入框能正常收到打字 "abc"（普通窗口消息 OK），
   但 RegisterHotKey（线程级+窗口级）的 WM_HOTKEY 都不触发

### 根因（两个 bug 叠加）
1. **RegisterHotKey 的 WM_HOTKEY 消息在本环境（PySide6 6.11 + Windows）不会被 Qt 事件循环派发**
   —— nativeEventFilter 收不到，线程级/窗口级注册均如此。普通窗口消息（WM_KEYDOWN）
   却正常，证明是 Qt 对系统级热键消息的处理问题。
2. **改用 GetAsyncKeyState 轮询后，`GlobalHotkey(HOTKEY, toggle)` 未保存对象引用**，
   实例被 Python GC 回收，轮询定时器随之停止（低级 bug）。

### 最终方案
弃用 RegisterHotKey，改用 **GetAsyncKeyState 主线程轮询**（QTimer 80ms，边沿触发、按住不重复）。
- v9 实测轮询 100% 可靠检测到真实按键
- 零依赖、无消息循环依赖、跨 Qt 版本稳定
- 必须保存 GlobalHotkey 实例引用（`hotkey = GlobalHotkey(...)`）

### 教训
1. demo 验证"注册成功" ≠ 验证"事件到达"——demo1 只验证了 RegisterHotKey 返回值，
   没验证真实按键触发回调，埋下了这个坑。
2. ctypes 调 Win32 API 时 HHOOK/HWND/LPARAM 等指针类型必须显式设 restype/argtypes，
   默认 c_int 在 64 位下截断。
3. 依赖对象生命周期（QTimer/热键对象）必须持有引用。

## 三、本轮踩过的其他坑（测试环境）

- **offscreen 平台差异**：Qt 画不出文字（无字体后端，PNG 纯白）；QClipboard 与系统剪贴板
  不互通（pyperclip 写入 Qt 读不到）；mimeData() 可能返回 None。
  → 测试用 PIL 生成图、Qt 剪贴板 API 写入、pixmap 判空。
- **Windows 路径分隔符**：save_media 用 os.path.join 产生反斜杠，前端/测试要兼容
  → 统一返回正斜杠 "media/xxx"。
- **退出段错误**：后台分类线程未结束时进程退出触发 segfault → 测试结尾 wait 线程 +
  os._exit 硬退出（跳过 Qt 析构）。
- **QButtonGroup.button() 不接受字符串**（只接受 int id）——误用残留代码。
